## 1. Лексика: нормативный список токенов (совпадает с реализацией)

Токены (см. `weave_lexer::TokenKind`): `Ident`, `Keyword(k)`, `Reserved`, `Int`, `Float`,
`Str`, `RawStr`, `ByteStr`, `Char`, комментарии (`LineComment`, `BlockComment`,
`DocComment`, `ModDocComment` — сохраняются в AST-trivia), операторы/пунктуация из
Фазы 1 §2.4, `AutoTerm`, `Error`, `Eof`.

**Правило автотерминации (нормативно, реализовано):** лексер вставляет `AutoTerm` на
`\n`, если последний значимый токен ∈ CanEnd = {Ident, литералы, `)`, `]`, `}`, `?`,
`true`, `false`, `self`, `Self`, `break`, `continue`, `return`} и он не `AutoTerm`/`;`.
Парсер трактует `AutoTerm` и `;` одинаково как разделитель инструкций; внутри
скобочных контекстов `( )` и `[ ]` парсер **игнорирует** `AutoTerm` (перенос внутри
вызова/списка легален); внутри `{ }` — значим. `&&`/`||` — лексическая ошибка W0012 с
восстановлением как `and`/`or` (одно сообщение, компиляция продолжается).

## 2. Полная грамматика v0.1 (дельта к Фазе 1 §3)

Фаза 1 §3 остаётся нормативной; ниже — завершающие уточнения.

```ebnf
(* Паттерны — полная форма *)
pattern      := "_" | literal | ident ("@" pattern)?        (* binding: x @ Some(_) *)
              | path tuple_pat? | struct_pat | tuple_pat
              | pattern "|" pattern | "&" pattern | range_pat ;
tuple_pat    := "(" pattern ("," pattern)* ","? ")" ;
struct_pat   := path "{" field_pat ("," field_pat)* (",".. | ","?)? "}" ;
field_pat    := ident (":" pattern)? ;
range_pat    := literal ".." literal | literal "..=" literal ;   (* только в match *)

(* Атрибуты: нормативный набор v0.1 *)
attribute    := "#[" attr "]" ;
attr         := "repr" "(" ("C"|"packed"|"transparent") ")"
              | "derive" "(" ident ("," ident)* ")"      (* Copy, Clone, Eq, Ord, Hash, Debug *)
              | "test" | "bench" | "deprecated" ("(" string_lit ")")?
              | "inline" ("(" ("always"|"never") ")")? | "cfg" "(" cfg_expr ")" ;

(* select — конкурентный выбор (§7) *)
select_expr  := "select" "{" select_arm ("," select_arm)* ","? "}" ;
select_arm   := (pattern "=" "recv" "(" expr ")" | "send" "(" expr "," expr ")"
              | "after" "(" expr ")") "=>" expr ;

(* Замыкания *)
closure      := "|" (param ("," param)*)? "|" ("->" type)? expr ;
(* Захват: только by-move или by-borrow, выводится region-анализом; нет ключевого
   слова move — если замыкание переживает область (spawn/detach), захват move обязателен
   и проверяется §4.3-R5. *)

(* Интерполяция строк: грамматика внутри Str-токена *)
str_part     := text | "{" expr (":" format_spec)? "}" ;
format_spec  := fill? align? sign? width? ("." precision)? type_char? ;
align        := "<" | ">" | "^" ;   sign := "+" ;
width        := int ;   precision := int ;   type_char := "x"|"X"|"b"|"o"|"e"|"?" ;
```
**Формат-спецификаторы (закрывает Ф1 §13.5):** `"{x:.2}"`, `"{n:>8}"`, `"{id:04x}"`,
`"{v:?}"` (debug). Десугаринг на comptime в вызовы `core.fmt.Display/Debug/Hex...`;
неверный спецификатор — ошибка компиляции с точным спаном внутри строки. Это
**единственный** механизм форматирования (нет printf).

**Полный десугаринг** (нормативный список): интерполяция → `fmt`; `for x in e` →
`match iter.next()`-цикл над comptime-развёрнутым итератором (Ф1 §5.3); `?` →
`match { Ok(v)=>v, Err(e)=>return Err(e.into_with_location(...)) }`; операторы →
вызовы трейтов `core.ops.Add/Sub/...` (перегрузка только через трейты); `a < b < c` —
запрещено грамматикой (сравнения неассоциативны, ошибка парсера с подсказкой `a < b and b < c`).

## 3. Правила типизации (двунаправленные)

Суждения: `Γ ⊢ e ⇒ τ ! ε` (синтез) и `Γ ⊢ e ⇐ τ ! ε` (проверка). Ключевые правила:

```
(VAR)        x:τ ∈ Γ                    (SUB)   Γ ⊢ e ⇒ τ'   τ' ≡ τ
             ─────────────                      ────────────────────
             Γ ⊢ x ⇒ τ ! {}                     Γ ⊢ e ⇐ τ ! ε
             (τ' ≡ τ — синтаксическое равенство после нормализации алиасов;
              подтипирования типов НЕТ — упрощение, дающее предсказуемый вывод)

(INT-LIT)    Γ ⊢ 42 ⇐ τ ! {}   если τ ∈ {i8..i64, u8..u64, usize, isize}
             и значение представимо в τ (иначе ошибка); ⇒-режим даёт i32.

(APP)        Γ ⊢ f ⇒ fn(τ₁..τₙ) -> τᵣ ! ε_f    Γ ⊢ eᵢ ⇐ τᵢ ! εᵢ
             ──────────────────────────────────────────────────────
             Γ ⊢ f(e₁..eₙ) ⇒ τᵣ ! ε_f ∪ ⋃εᵢ
             (эффект вызова = эффект сигнатуры f; для дженерик-переменной
              эффекта E — подстановка из инстанцирования)

(IF)         Γ ⊢ c ⇐ bool ! ε₁   Γ ⊢ e₁ ⇐ τ ! ε₂   Γ ⊢ e₂ ⇐ τ ! ε₃
             ──────────────────────────────────────────────────────
             Γ ⊢ if c {e₁} else {e₂} ⇐ τ ! ε₁∪ε₂∪ε₃
             (if без else имеет тип (); обе ветви проверяются против одного τ —
              нет вычисления «общего супертипа», его не существует без подтипирования)

(MATCH)      Γ ⊢ scrut ⇒ τₛ ! ε₀    ∀i: Γ,bind(pᵢ:τₛ) ⊢ eᵢ ⇐ τ ! εᵢ
             exhaustive({p₁..pₙ}, τₛ)
             ──────────────────────────────────────────────────────
             Γ ⊢ match scrut {pᵢ => eᵢ} ⇐ τ ! ⋃ε
             (exhaustive — алгоритм полезности Maranget'а, как в rustc)

(BLOCK)      инструкции проверяются последовательно, let расширяет Γ;
             тип блока = тип последнего выражения без терминатора, иначе ().

(CLOSURE)    Γ ⊢ |x:τ₁| e : проверка e в Γ,x:τ₁ ⇒ τ₂ ! ε
             ────────────────────────────────────────────
             Γ ⊢ |x| e ⇐ fn(τ₁) -> τ₂ ! ε'   при ε ⊆ ε'
             (эффекты замыкания ⊆ эффектов ожидаемого fn-типа; типы параметров
              берутся из check-контекста — аннотации нужны только в ⇒-режиме)
```

Разрешение методов `x.f(a)`: (1) собственные методы типа `x`; (2) методы трейтов
в области видимости (`use` импортирует и impl-ы трейта); неоднозначность — ошибка
с перечислением кандидатов, авто-`&`/`&mut`-адъюстация приёмника как в Rust.
Дженерик-инстанцирование: унификация только на границе вызова (локальная, не глобальная);
несводимые переменные типа — ошибка «type annotation needed» с точным спаном.

## 4. Формальные правила регионов (уточнение Ф1 §5.2)

К суждению добавляется контекст займов Λ (loan set). Ключевые правила MIR-уровня:

```
(BORROW)     p — place, доступное в текущей точке; создаётся loan ℓ = (p, shared|mut)
             Λ' = Λ ∪ {ℓ};  &p : &τ с origin {ℓ}
(MUT-EXCL)   в каждой программной точке для каждого place p:
             |{ℓ ∈ live(Λ): ℓ.place пересекается с p, ℓ.kind = mut}| ≤ 1
             и (∃ live mut loan на p) ⟹ (нет live shared loans на p ∧ нет прямых чтений/записей p)
(KILL)       move(p) или drop(p) убивает все loans, чей place пересекается с p;
             использование ссылки с убитым loan в её origin — ошибка W0100
             (диагностика: точка займа / точка kill / точка использования — Ф1 §5.2.4)
(CALL)       для вызова f с provenance-клаузой `-> &τ from p₁..pₙ`:
             origin(результата) = ⋃ origin(аргументов на позициях p₁..pₙ)
(RETURN)     origin возвращаемой ссылки ⊆ ⋃ origin(параметров из from-клаузы);
             ссылка на локальное place в возврате — ошибка W0101 «returns reference to local»
(R5-ESCAPE)  значение, захваченное spawn/detach-блоком, не содержит live loans
             (изолированные кучи §7); Handle<T> — place с регионом ⊆ лексический scope
```
Живость origin-ов вычисляется как в NLL: fixpoint по CFG (liveness ссылок,
транзитивно через присваивания). Набросок звуковости: инварианты (MUT-EXCL) + (KILL)
дают отсутствие алиасов при мутации и отсутствие висячих ссылок на каждом шаге
малошаговой семантики MIR; полное доказательство — по образцу RustBelt, бюджетируется
на Stage 0 peer-review [D4], вне объёма этого документа.

## 5. Формальные правила эффектов (уточнение Ф1 §6)

```
(E-LEAF)     примитив с внутренним эффектом e (syscall-шлюзы stdlib): ε = {e}
(E-CALL)     эффект вызова из (APP); проверка гранта: ε_callee ⊆↓ Δ
             где ⊆↓ — включение с учётом поддеревьев (fs.Read ⊆↓ {fs})
(E-DECL)     pub fn f() ! ε_decl { body }: вывести ε_body; ошибка если ε_body ⊄↓ ε_decl
             (объявлено меньше, чем используется); предупреждение W0201 если
             ε_decl строго шире ε_body (мёртвый грант — сузить)
(E-PRIV)     приватная fn: ε = fixpoint по графу вызовов пакета (SCC-итерация;
             рекурсия сходится, т.к. решётка конечна)
(E-WITH)     with_capabilities(ε₀) { body }: body проверяется при Δ' = Δ ∩↓ ε₀
(E-REQ)      effect db {...} requires ε_r: тела функций пакета, декларирующих db.*,
             получают право на ε_r; наружу виден только db.* + запись в манифесте
(E-MAIN)     Δ(main) = [capabilities] из weave.toml; отсутствие секции = {} (чистый main)
(E-COMPTIME) comptime-код: Δ = {comptime.Emit} — ничего больше, без исключений
```

## 6. Семантика исполнения: отмена, cleanup, паника (закрывает Ф1 §14.2)

Нормативный порядок завершения процесса P в scope S (все случаи):
1. **Нормальный выход**: локальные drop-ы в обратном порядке объявления → куча-регион P освобождается целиком → результат публикуется в Handle.
2. **Паника в P**: unwind только стека P (drop-ы в обратном порядке) → Handle переходит в состояние Panicked(info) → S получает сигнал.
3. **Отмена P** (S отменяет из-за ошибки сиблинга или собственной отмены): P продолжает до ближайшего yield-point (канальная операция, I/O, `yield_point()`) → в точке yield поднимается `Cancelled` → выполняются `on_cancel`-блоки **в LIFO-порядке лексической вложенности от точки отмены наружу**, каждый в контексте `Δ_cancel = Δ_P` (те же гранты), с жёстким бюджетом времени (default 1s, конфигурируемо `scope with_cancel_budget(...)`); превышение бюджета = паника процесса → далее unwind как в (2), но `on_cancel` уже выполненных уровней не повторяются.
4. **Правило S**: scope завершается только после того, как **все** дочерние Handle в терминальном состоянии (Done/Panicked/Cancelled). Порядок: сигнал отмены рассылается всем детям одновременно; join — в порядке завершения. Ошибка по умолчанию: первый Err/паника ребёнка → отмена остальных → re-raise после полного сбора (никогда не раньше — гарантия отсутствия осиротевших процессов). `scope supervise`: терминальные состояния доставляются как значения, каскада нет.
5. **Вложенные scope**: внутренний scope — обычное выражение в стеке P; при unwind/отмене P внутренний scope проходит собственную процедуру (4) до продолжения unwind наружу. Инвариант: **дерево процессов сворачивается строго снизу вверх**.
6. `on_cancel` не выполняется при нормальном выходе и при панике (только при отмене); для «всегда»-cleanup служит `defer { }` (добавлено в грамматику: `defer_stmt := "defer" block`; исполняется при любом выходе из блока, LIFO). Обоснование разделения: смешение «компенсация отмены» и «освобождение ресурса» в одном механизме — источник ошибок в Go (`defer` + ctx) и Java (finally).

## 7. Семантика `select` (закрывает Ф1 §14.3)

`select` блокируется до готовности ≥1 ветви; при нескольких готовых — **равномерно случайный выбор** (как Go; честность без глобальной очереди). Ветви: `recv`, `send`, `after(duration)` (таймаут, эффект `time.Read`). Отмена процесса в блокировке select — это yield-point (§6.3). Закрытый канал: recv-ветвь получает `None` (тип ветви `Option<T>`), send в закрытый канал — `Err(Closed)`, не паника. Гарантия: за одно срабатывание select выполняется ровно одна ветвь, атомарно относительно каналов.

## 8. Object safety (закрывает Ф1 §14.3): трейт объектобезопасен ⟺ все методы: (а) приёмник `self`-по-ссылке (`&self`/`&mut self`); (б) без дженерик-параметров типов (дженерик-эффекты допустимы — мономорфизируются на границе виртуального вызова в супермножество); (в) `Self` не встречается вне позиции приёмника; (г) нет ассоциированных функций без приёмника. Нарушение при построении `Box<trait T>` — ошибка с перечислением нарушивших методов.

## 9. comptime: host/target (закрывает Ф1 §13.4). Comptime-вычисление исполняется на host, но **типизируется относительно target**: `usize`/указательные размеры, эндианность, `cfg`-флаги — от target; host-JIT реализует target-семантику программно (как Zig). Следствие: один и тот же comptime-результат для любой host-платформы — требование воспроизводимости (Ф1 §9.2) распространяется на кросс-компиляцию. `comptime.Emit` производит HIR-фрагменты, верифицируемые обычным тайпчеком немедленно при вставке.
